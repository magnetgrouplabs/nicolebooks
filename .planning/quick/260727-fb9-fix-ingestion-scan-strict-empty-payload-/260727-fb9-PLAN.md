<objective>
Fix the app-breaking Phase 2 regression where `ingestion:scan` always rejects, and add the
regression coverage whose absence let it ship green through an entire phase.

Purpose: the Bills screen "Scan now" button has never been able to succeed. `src/main/ipc/ingestion.ts:41`
runs `ScanRequestSchema.parse(raw)` against a strict-empty schema, but the preload invokes the channel
with no argument, so `raw` is `undefined` and `z.object({}).strict().parse(undefined)` throws
`Invalid input: expected object, received undefined`. Confirmed twice: empirically on the running app
with a Playwright probe, and by source reading. ING-01 and ING-02 are marked Complete in REQUIREMENTS.md
but are in fact non-functional.

The one-character fix is the easy half. The important half is the test: no unit or e2e spec ever
*invokes* `window.api.ingestion.scan()` — `e2e/ipc-boundary.spec.ts` only asserts the method exists on
the bridge, which a permanently-rejecting handler passes trivially.

Output: the normalized parse in `src/main/ipc/ingestion.ts`, a handler-level unit regression, and an
e2e invocation proof.
</objective>

<critical_constraint>
The preload's `scan` is ZERO-ARITY: `scan: () => ipcRenderer.invoke(Channels.ingestionScan)`. It
silently discards anything a caller passes. Therefore a "smuggled payload must reject" assertion
written at the RENDERER level (`window.api.ingestion.scan({...})` inside a Playwright evaluate)
would RESOLVE, not reject — the payload never crosses the bridge. Writing that assertion as an
e2e test would produce a false failure and tempt someone to "fix" it by weakening the schema.

The strict-empty gate is reachable only at the main-process handler, which is exactly where Task 2
tests it. Task 3 asserts only the resolve half at the renderer level. This split is deliberate.
</critical_constraint>
</context>
