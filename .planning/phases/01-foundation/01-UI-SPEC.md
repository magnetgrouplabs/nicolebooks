# Phase 1: UI Design Contract

> Visual and interaction contract for the branded cross-platform Electron shell. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Every value below is pulled verbatim from the canonical Magnet Group token file (`../themagnetgroup/brand-guide/agents/tokens.json`, v2026.06.1) or from a locked Phase 1 decision (D-01 through D-15 in `01-CONTEXT.md`). Nothing here is invented. Source is cited per row. All hyphens are plain hyphens; this file contains no dash characters other than the plain hyphen.

---

## Scope Recap

Phase 1 ships the app frame only, no product features (D-07): a persistent branded header (wordmark + connection-status slot), a persistent 280px left sidebar (Bills, History, Settings), a swappable content region rendering placeholder screens, and a permanent "Secret store" health indicator on the Settings screen (D-11). It locks the theme, layout frame, and states that Phases 2 through 8 build on.

## Layout Frame (structural contract)

The frame is a real, reusable app shell (D-07), not a splash. Fixed structural dimensions come straight from `tokens.json layout`.

| Element | Spec | Source |
|---------|------|--------|
| Window color scheme | Follows OS preference via Electron `nativeTheme` + `prefers-color-scheme`. No in-app toggle in v1. | D-03 |
| Header (top bar) | Full width, height 56px, structural radius 0, sits above content (`elevation.nav` = z-index 20). Carries the wordmark (left) and the connection-status slot (right). | D-08; tokens.json `layout.navHeight` = 56px, `radiusUsage.structural` = 0, `elevation.nav` = 20 |
| Sidebar (left nav) | Fixed width 280px, full height below header, structural radius 0, three icon+text destinations. | D-09; tokens.json `layout.sidebarWidth` = 280px, `radiusUsage.structural` = 0 |
| Nav item | Full sidebar width, min height 40px, icon (20px) + text label, 12px gap, 12px horizontal padding. | tokens.json `space.10` = 40px, `space.3` = 12px |
| Content region | Swappable single-child area to the right of the sidebar, below the header, background = dominant surface, 24px padding. | D-07; tokens.json `space.6` = 24px |
| Default active destination on launch | Bills | D-09 (first destination) |
| Structural radius | 0 for sidebar, header, and workspace panels; never rounded. | tokens.json `radiusUsage.structural` = 0; D-09 |

## Spacing Scale

Declared values (all multiples of 4; sourced from `tokens.json space`, which is a 4px-base scale, 1 = 0.25rem = 4px):

| Token | Value | Usage | Source |
|-------|-------|-------|--------|
| xs | 4px | Icon-to-label micro gaps, hairline insets | tokens.json `space.1` |
| sm | 8px | Compact element spacing, status dot to label gap | tokens.json `space.2` |
| md | 16px | Default element spacing, card inner padding | tokens.json `space.4` |
| lg | 24px | Content region padding, section padding | tokens.json `space.6` |
| xl | 32px | Layout gaps, empty-state vertical rhythm | tokens.json `space.8` |
| 2xl | 48px | Major section breaks | tokens.json `space.12` |
| 3xl | 64px | Page-level spacing, empty-state top offset | tokens.json `space.16` |

Additional in-scale steps available from tokens.json when needed: 12px (`space.3`), 20px (`space.5`), 40px (`space.10`).

Exceptions (fixed structural layout dimensions, not part of the spacing rhythm; both are multiples of 4): sidebar width 280px, header height 56px, nav-item min height 40px. Interactive targets (nav items) meet a 40px minimum height for comfortable pointer targets.

## Typography

Phase 1 declares four type roles and two weights only, drawn from the token scale. Jost for headings and the wordmark, DM Sans for everything else (D-04). Tracking stays `normal` (0) because every Phase 1 size is at or below the 30px threshold where the brand tightening curve begins (tokens.json `trackingBySize`: 24px and below = 0).

| Role | Size | Weight | Line Height | Font | Source |
|------|------|--------|-------------|------|--------|
| Heading (empty-state titles) | 24px (1.5rem) | 600 semibold | 1.2 tight | Jost | tokens.json `font.size.2xl`, `weight.semibold`, `lineHeight.tight` |
| Wordmark / display | 20px (1.25rem) | 600 semibold | 1.2 tight | Jost | tokens.json `font.size.xl`, `weight.semibold`, `lineHeight.tight` |
| Body (empty-state and settings copy) | 16px (1rem) | 400 regular | 1.5 normal | DM Sans | tokens.json `font.size.base`, `weight.regular`, `lineHeight.normal` |
| Label (nav items, status slot, health indicator) | 14px (0.875rem) | 400 regular; 600 semibold for the active nav item | 1.35 snug | DM Sans | tokens.json `font.size.sm`, `weight.regular`/`semibold`, `lineHeight.snug` |

Declared sizes: 14, 16, 20, 24 (four). Declared weights: 400 regular, 600 semibold (two). The active-nav-item emphasis reuses the 600 weight already declared, so no third weight is introduced. Foreground text color normalizes to `#343434` in light mode (D-05, tokens.json `surface.fg`), not the website's `#1d1d1f`.

## Color

The brand system carries both light and dark palettes; both are wired in Phase 1 and the window follows the OS color scheme (D-03). Values are verbatim from `tokens.json`.

### Light mode (60 / 30 / 10)

| Role | Value | Usage | Source |
|------|-------|-------|--------|
| Dominant (60%) | `#ffffff` | Window and content-region background, cards | tokens.json `surface.bg` / `surface.card` |
| Secondary (30%) | `#f5f5f7` | Sidebar surface, header surface, muted panels | tokens.json `surface.secondary` / `surface.muted` |
| Accent (10%) | `#6c00ff` electric violet | See reserved-for list below | tokens.json `color.brand.primary` |
| Destructive | `#ff3b30` | Declared in theme for later phases; not used in Phase 1 (no destructive actions) | tokens.json `semantic.destructive` |

Supporting light-mode tokens carried into the theme: foreground `#343434` (`surface.fg`, D-05), muted foreground `#6e6e73` (`surface.mutedFg`, canonical value per D-01, not the site's `#48484a`), border `#e5e5ea` (`surface.border`), input `#e5e5ea` (`surface.input`), ring `#6c00ff` (`surface.ring`), accent-foreground `#343434` (`brand.accentFg`), secondary lavender `#c77dff` (`brand.accent`, reserved for later phases).

### Dark mode

| Role | Value | Usage | Source |
|------|-------|-------|--------|
| Dominant (60%) | `#1a1a1a` | Window and content-region background | tokens.json `dark.bg` |
| Secondary (30%) | `#2a2a2a` | Sidebar surface, header surface, cards/popovers | tokens.json `dark.secondary` / `dark.card` (`#242424` for card) |
| Accent (10%) | `#6c00ff` brand primary; ring/focus uses `#8f33ff` (lighter primary for visibility on dark) | Active nav, focus ring | tokens.json `color.brand.primary`, `dark.ring` |

Supporting dark-mode tokens: foreground `#f0f0f0` (`dark.fg`), muted foreground `#a0a0a0` (`dark.mutedFg`), border `#3a3a3a` (`dark.border`), input `#3a3a3a` (`dark.input`), card `#242424` (`dark.card`), popover `#2a2a2a` (`dark.popover`).

### Accent reserved for (Phase 1)

Accent (`#6c00ff`, ring `#8f33ff` in dark) is used ONLY for:
1. The active/selected sidebar navigation item (violet text plus a violet left-edge indicator bar).
2. The `focus-visible` ring on interactive elements (nav items and any focusable control), using the ring token and `shadow.focus` = `0 0 0 3px rgba(108, 0, 255, 0.32)`.

Accent is NOT applied to all interactive elements, body text, borders, or the wordmark. The wordmark is plain `#343434` (light) / `#f0f0f0` (dark) text.

### Status colors (health indicator and connection slot, distinct from brand accent)

These are semantic status signals, not the 10% brand accent. Sourced from `tokens.json semantic`.

| Signal | Value | Where | Source |
|--------|-------|-------|--------|
| Secret store OK | `#28a745` success green | Settings health indicator dot/icon when keychain round-trip succeeds | tokens.json `semantic.success` |
| Secret store unavailable | `#ff3b30` destructive red | Settings health indicator dot/icon when keychain is unreachable | tokens.json `semantic.destructive` |
| Connection slot placeholder (Phase 1) | `#6e6e73` neutral muted | Header connection-status slot neutral dot + label, before Phase 4 populates real QuickBooks health | tokens.json `surface.mutedFg`; D-08 |

Semantic warning `#f59e0b` and info `#6c00ff`, plus the five chart colors, are carried into the theme now for reuse by later phases (for example confidence flags in Phase 6) even though nothing consumes them in Phase 1 (D-06).

## Copywriting Contract

Phase 1 copy is minimal (no product features). No personal, owner, or founder names appear in any copy (project rule). No dash characters are used.

| Element | Copy |
|---------|------|
| Wordmark | `NicoleBooks` (plain text, no logo) |
| Primary CTA | None. Phase 1 ships no feature actions, so there is no primary call to action on any screen. The pill-radius primary button contract (`#6c00ff` fill, `#ffffff` label, `radius.pill`) is documented here for later phases only. |
| Empty state heading | `No bills to review` (Bills, the default landing screen) |
| Empty state body | `Bills you import will appear here for review before they post to QuickBooks.` |
| Error state | Secret store unavailable: `Secret store unavailable.` with supporting line `This machine's secure keychain could not be reached, so credentials cannot be stored yet. Restart NicoleBooks; if it keeps happening, this machine cannot store secrets securely.` |
| Destructive confirmation | None. Phase 1 contains no destructive actions. |

### Per-screen copy (all three destinations + header slot)

| Surface | State | Copy |
|---------|-------|------|
| Header connection-status slot | Phase 1 neutral placeholder (Phase 4 replaces with real QuickBooks health) | Neutral gray dot + `Not connected` |
| Bills screen | Empty placeholder | Heading `No bills to review`; body `Bills you import will appear here for review before they post to QuickBooks.` |
| History screen | Empty placeholder | Heading `No history yet`; body `Batches you send to QuickBooks will be listed here, along with the entries in each.` |
| Settings screen | Hosts the Secret store health indicator (D-11); connection and AI settings arrive in later phases | Section label `Secret store`; healthy state `Secret store: OK` with supporting line `Your machine's secure keychain is available and working.`; unavailable state `Secret store: unavailable` with the Error state copy above. A muted note reads `Connection and model settings will appear here in a later update.` |
| Nav labels | Static | `Bills`, `History`, `Settings` (D-09) |

### Suggested lucide icons

Bills → `Receipt`; History → `History`; Settings → `Settings`; Secret store OK → `ShieldCheck`; Secret store unavailable → `ShieldAlert`; connection slot neutral → filled `Circle` dot. Executor may substitute equivalents from lucide if a closer match exists.
