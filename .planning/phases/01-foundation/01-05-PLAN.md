Output: Working settings, secrets, and theme IPC handlers registered in main, each hardened against malformed or untrusted requests.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer to main handler | Untrusted invoke crosses here; each handler validates the sender and Zod-parses the payload before acting |
| main to OS resources | Handlers are the only path from a renderer request to SQLite (settings), safeStorage (secrets), and nativeTheme (theme) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Tampering | ipcMain.handle handlers | mitigate | assertTrustedSender(event) then Schema.parse(payload) before every privileged call, on all handlers; a handler missing either step fails the security gate (Task 1) |
| T-01-05 | Information Disclosure | secrets/settings handlers | mitigate | Never log secret values; the unavailable path returns null, not a raw stack trace to the renderer (Task 1) |
| T-01-06 | Tampering | settings SQL | mitigate | Prepared statements with bound parameters and ON CONFLICT UPSERT; no key/value interpolation into SQL (Task 1) |
| T-01-01 | Elevation of Privilege | main bootstrap | mitigate | Registration preserves the hardened window posture from 01-01; safeStorage and handlers initialize only after app.whenReady (Task 2) |
</threat_model>
