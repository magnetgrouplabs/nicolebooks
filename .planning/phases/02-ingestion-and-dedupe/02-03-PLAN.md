## Phase Goal

**As a** non-technical accounts-payable user, **I want to** drop bills into one flat inbox and load them on a manual scan with already-posted duplicates caught up front, **so that** I get a clean, non-duplicate batch to process without any folder-naming discipline.

This plan delivers **MVP Slice 3**: the file-materialization guard. After this plan, cloud-sync placeholders (OneDrive/iCloud online-only files) and partially-written files are detected by metadata only — never downloaded, never hashed half-complete — flagged "not downloaded yet, re-scan shortly", and surfaced for re-scan. This closes SC4 and the second half of ING-03, and it guarantees a real bill is never silently lost.

<objective>
Add the "metadata-first, bytes-last" materialization gate to the scan pipeline. Before hashing any file, the scan runs two independent gates: (1) a placeholder check that reads metadata only (macOS: `size>0 && blocks===0`, or a `.<name>.icloud` sibling sentinel; Windows: a single batched `execFile` attribute read testing `FILE_ATTRIBUTE_OFFLINE` / `RECALL_ON_DATA_ACCESS` / `RECALL_ON_OPEN`), and (2) a bounded size+mtime settling poll for partial writes. Files failing either gate become `not-ready-skipped` and are surfaced for re-scan. The gates run BEFORE the SHA-256 stream, because reading bytes is exactly what forces a placeholder to download.

Purpose: This is SC4 and the placeholder half of ING-03/D-11 — "waits for files to fully materialize before hashing, so cloud-sync placeholder files and partially written files are not processed as if complete", and "does NOT attempt to force-download placeholders". A silently-lost bill is the worst outcome for a non-technical AP user (CONTEXT `<specifics>`).

Output: A scan of an inbox containing a simulated placeholder and a still-writing file flags both `not-ready-skipped` without hashing them, while real local files still load.

**Flagged decision encoded here (inconclusive-detection fallback):** the scan LOADS on total detection failure and SKIPS only on positive placeholder evidence. Concretely: if the Windows attribute read throws or returns nothing (PowerShell/attrib unavailable), the file is treated as materialized and hashed, rather than false-skipping every real local bill. Skipping requires a positive OFFLINE/RECALL bit (Windows) or `blocks===0`/`.icloud` sentinel (macOS). This favors "never false-skip a real bill" over "never ever download", within D-11's spirit that skipped files are always surfaced and re-scannable (RESEARCH Section 1.4 + Open Question 1).
</objective>

| Boundary | Description |
|----------|-------------|
