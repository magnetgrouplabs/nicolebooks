## Phase Goal

**As a** non-technical accounts-payable user, **I want to** drop bills into one flat inbox and load them on a manual scan with already-posted duplicates caught up front, **so that** I get a clean, non-duplicate batch to process without any folder-naming discipline.

This plan delivers **MVP Slice 1** of that goal: the end-to-end walking path — click "Scan now" on the Bills screen, and every supported file loads (with today's date), while unsupported files are surfaced and OS junk is ignored. Duplicate-catch (Slice 2, plan 02-02) and not-ready/placeholder skipping (Slice 3, plan 02-03) layer on top of this same path.

<objective>
Build the ingestion front-door as a working vertical slice: a new `ingestion` IPC channel group (main-only fs/hash/db behind the Phase 1 trust boundary), the `posted_file_hashes` dedupe-ledger migration, and a Bills-screen "Scan now" button that enumerates the flat inbox, classifies file types by extension, streams a SHA-256 per supported file, stamps the batch with the processing date, and renders a minimal loaded-results surface.

Purpose: This is the thinnest end-to-end path that proves ingestion works button-to-database-and-back. It establishes every seam (contract, migration, ingestion modules, IPC handler, preload, results UI) that Slices 2 and 3 extend. Materialization detection and the ledger dedupe check are intentionally deferred to later slices; this slice treats every enumerated file as materialized and runs no ledger check.

Output: A user can configure/see a default inbox, drop supported bills, click "Scan now", and see them loaded with today's date plus a summary; unsupported files appear in a skipped summary.

**Flagged decision encoded here (Design B):** `migration0002` creates `posted_file_hashes` as a POSTED-ONLY ledger. Phase 2 is read-only on it (the check arrives in plan 02-02); the row-insert that marks a hash sent is a Phase 7 responsibility. No Phase 2 code path writes this table. This is the RESEARCH-recommended split (Section 3, Design B), the most literal reading of D-08.
</objective>

```typescript
export type ScanFileStatus =
  | 'loaded'
  | 'duplicate-excluded'    // ledger hit (plan 02-02)
  | 'duplicate-in-batch'    // within-scan copy (plan 02-02)
  | 'not-ready-skipped'     // placeholder / still-writing (plan 02-03)
  | 'unsupported-skipped'   // wrong file type (this slice)

export interface ScanFile {
  filename: string
  status: ScanFileStatus
  hash?: string
  sizeBytes?: number
  postedAt?: string
}

export interface ScanResult {
  batchEntryDate: string    // local day of scan, 'YYYY-MM-DD' (D-05)
  inboxPath: string
  files: ScanFile[]
  summary: { total: number; loaded: number; duplicates: number; notReady: number; unsupported: number }
}

export interface IngestionApi {
  resolveInbox(): Promise<{ path: string; created: boolean }>
  chooseInbox(): Promise<{ canceled: true } | { canceled: false; path: string }>
  scan(): Promise<ScanResult>
}
```
