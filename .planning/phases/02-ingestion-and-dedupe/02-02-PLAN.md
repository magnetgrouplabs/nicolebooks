## Phase Goal

**As a** non-technical accounts-payable user, **I want to** drop bills into one flat inbox and load them on a manual scan with already-posted duplicates caught up front, **so that** I get a clean, non-duplicate batch to process without any folder-naming discipline.

This plan delivers **MVP Slice 2**: the duplicate-catch behavior on top of Slice 1's working scan. After this plan, re-dropping a file that was already posted to QuickBooks is caught, flagged, and excluded by default (with a one-click override), and byte-identical copies within a single scan collapse — so Nicole never double-enters a bill.

<objective>
Add exact-file deduplication to the scan slice. Compute-all-hashes-then-group: after Slice 1 hashes every supported file, group the batch by hash for within-scan collapse (D-10), then check each distinct hash against the `posted_file_hashes` ledger (D-08/D-09). Ledger hits become `duplicate-excluded` (surfaced with the posted date, excluded from the batch by default); the Bills screen gains a one-click "include anyway" override. Within-scan byte-identical copies become `duplicate-in-batch`.

Purpose: This is the heart of ING-04 — "compute a SHA-256 file hash for each document and skip-and-flag any exact file already posted, excluded by default with an override." It closes the "re-dropping an already-entered file creates no duplicate work" guarantee (SC3).

Output: A scan of an inbox containing an already-posted file and two identical copies shows the posted file as duplicate-excluded (with its posted date and an include-anyway control) and one of the copies as duplicate-in-batch.

**Flagged decision encoded here (Design B):** `ledger.ts` is READ-ONLY — a single prepared `SELECT posted_at, original_filename FROM posted_file_hashes WHERE hash = ?`. Phase 2 has no insert/update path against this table; the "mark sent" write is owned by Phase 7. A pending file re-scanned reloads automatically because no ledger row exists for it yet. This is the RESEARCH-recommended split (Section 3, Design B); D-08 confirmed.
</objective>
